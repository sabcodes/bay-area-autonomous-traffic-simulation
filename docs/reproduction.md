# Reproduce the final research package

Run commands from the repository root unless an absolute script path is used.
Three checks answer different questions: saved-package verification, exact local
input availability, and a full simulation replay. The package checker uses only
Python >=3.11 standard library and Git; it does not load SUMO, NumPy or Matplotlib.

## Clone-only saved-evidence verification

```sh
git clone https://github.com/sabcodes/bay-area-autonomous-traffic-simulation.git
cd bay-area-autonomous-traffic-simulation
# Until the M8 PR merges, select its published branch:
git switch codex/m8-research-package
python3 scripts/build_m8_package.py --check
```

This writes nothing. It recomputes 52 M7 paired headline records and M3 station
scores, verifies accepted M7 report/audit/config binding and simulator hashes,
then compares generated bytes and the content manifest. It needs a Git checkout
because the manifest enumerates versioned files. It checks saved evidence and
content integrity, not independent raw trajectories or field truth. Git history
and PR review provide the trust anchor; anyone can generate new hashes.

To intentionally regenerate the tables and manifest after an authorized package
change, stage new package source/docs first, then build and check:

```sh
git add docs scripts tests reports/m8 README.md CONTEXT.md
python3 scripts/build_m8_package.py
python3 scripts/build_m8_package.py --check
```

A changed file in the manifest, missing file, altered accepted M7 report, wrong
source hash, missing seed or nonfinite headline value causes nonzero exit.
Do not regenerate the manifest to hide an unexplained difference.

## Environment and regression

The measured runtime is SUMO and libsumo 1.27.1 on Apple Silicon macOS. The
runtime harness rejects an incompatible engine. Project package ranges alone
are not a complete portable environment lock: use the exact versions below
for a replay; different platforms/builds can require additional validation.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install '.[dev,reports]'
.venv/bin/python -m pip install 'eclipse-sumo==1.27.1' 'libsumo==1.27.1' 'traci==1.27.1' 'sumolib==1.27.1'
PYTHONPATH=src .venv/bin/python -m pytest -q
.venv/bin/ruff check src tests scripts
git diff --check
```

The regression suite includes small real-engine integration tests. A clone-only
package check is lighter and does not require a runtime installation. Nothing
in these commands launches the full 54-run campaign.

## Local data and accepted input preparation

PeMS raw files and large generated runtime outputs are ignored by Git. Obtain
the authorized District 4 Station 5-Minute exports from [PeMS](https://pems.dot.ca.gov/)
and retain their original names under `data/pems/`. The selected M3 dates are
2025-10-07, 08, 09, 10, 14, 15 and 16. Full M1 inventory replication uses the
original 13-date selection recorded in [the sensor audit](us101-sensor-audit.md).
Station Metadata exports are `d04_text_meta_2025_08_27.txt` and
`d04_text_meta_2025_10_16.txt` under `data/pems/metadata/`. The frozen config
also records hashes for the local 2024 Caltrans District 4 ramp and truck Excel
sources. Follow the [M3 demand ledger](m3-demand-ledger.md) for their provenance.
The checker enumerates every exact required path; a clone alone lacks them.

In a fresh local reproduction area, restore the accepted compressed network and
prepare the profiles using the same raw downloads, filters and file set:

```sh
mkdir -p outputs/us101_corridor
gzip -dc network/us101_corridor/accepted_m2.net.xml.gz > outputs/us101_corridor/us101_corridor.net.xml
PYTHONPATH=src .venv/bin/python -m bay_area_traffic_sim summarize-pems-stations \
  --station-ids-file configs/us101_corridor_station_ids.json \
  --station-ids-key accepted_corridor_station_ids --lane-types ML \
  --output outputs/pems_calibration/us101_corridor_m1_station_profiles.json
PYTHONPATH=src .venv/bin/python -m bay_area_traffic_sim summarize-pems-stations
PYTHONPATH=src .venv/bin/python scripts/prepare_m3_upstream_proxy.py
python3 scripts/build_m8_package.py --check-local-inputs
```

On an existing research workspace, inspect before writing: those preparation
commands replace generated inputs. Preserve accepted inputs/raw runs. The
separate prerequisite checker only reads and hashes the nine paths in
`configs/us101_human_baseline_m3_frozen.json`. If it reports missing or mismatched
files, stop and restore the original input set; do not change frozen hashes or
use held-out results for tuning. Matching the raw file set matters because the
profile provenance includes source names/content. The checker does not prove
that old raw simulation outputs are available.

## Fresh full M7 replay and independent raw audit

This is a separate, potentially lengthy run with large trajectory output.
Keep this cloud-managed directory downloaded. Ensure storage headroom; the
project's operational policy pauses long-running work at or below 5 GiB free.
No new full campaign was required or run for M8.

Create a fresh config ID; leave every scientific setting unchanged. The ID
below is illustrative and must not already exist. The harness rejects an
existing campaign directory.

```sh
.venv/bin/python - <<'PY'
import json
from pathlib import Path
p = Path('outputs/m8_replay_config.json')
assert not p.exists(), 'Choose a fresh config path and campaign ID'
c = json.loads(Path('configs/us101_m7_sensitivity.json').read_text())
c['campaign_id'] = 'm8_replay_2025_10_08'
assert not Path('outputs/us101_corridor/m7', c['campaign_id']).exists()
p.write_text(json.dumps(c, indent=2) + '\n')
PY
PYTHONPATH=src .venv/bin/python scripts/run_m7_sensitivity.py --config outputs/m8_replay_config.json
.venv/bin/python scripts/audit_m7_results.py \
  --config outputs/m8_replay_config.json \
  --report outputs/us101_corridor/m7/m8_replay_2025_10_08/report.json \
  --output outputs/m8_replay_audit.json
.venv/bin/python scripts/summarize_m7_results.py \
  --report outputs/us101_corridor/m7/m8_replay_2025_10_08/report.json \
  --audit outputs/m8_replay_audit.json --output outputs/m8_replay_presentation
```

The raw audit also expects the historical M6 reports/detector references used
for exact replay, which are versioned; it reads the replay's fresh native files.
M7 config IDs affect output locations and config hashes, so compare scientific
metrics and frozen input/source provenance, not whole-report byte identity.
Do not replace accepted `reports/m7/` with the replay or rebuild M8 against it.
The native metadata script currently targets the canonical M7 report; its saved
54-run result is versioned, and it is not a configurable fresh replay checker.
